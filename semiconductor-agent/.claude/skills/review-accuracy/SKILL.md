# 기술 정확성 검수 (QA 게이트)

accuracy-reviewer 에이전트가 큐레이터 산출물의 반도체 공학적 정확성을 검수하는 절차.
생성-검증 패턴의 "검증" 측 — 이 게이트를 통과한 콘텐츠만 코드에 반영된다.

## 검수 = 경계면 교차 비교

"있는지"가 아니라 "맞는지"를, 경계면을 교차 비교해 본다.

### 1. 질문 ↔ key_points
key_points가 질문에 실제로 답이 되는 채점 기준인지, 누락·오류가 없는지. 도메인 페르소나
기준으로 본다:
- **소자**: MOSFET/FinFET/GAA 1차 원리(밴드, Vth, mobility, SCE)
- **공정**: CVD/ALD step coverage·conformality·selectivity
- **회로**: 센스앰프/차지펌프 마진, 노이즈, 타이밍
- **트렌드**: EUV/HBM/GAA/패키징 로드맵·양산성

### 2. 모범답안 ↔ 질문 ↔ 물리
모범답안이 질문에 정확히 답하고 수식·메커니즘이 물리적으로 옳은지. 흔한 오류:
- Vth 온도 의존성 방향(온도↑ → Φf 감소 → Vth 감소)
- ALD self-limiting을 "얇게 쌓는다"로만 설명(saturation 원리 누락)
- LaTeX 표기 오류
- HBM/노드 양산 시점·세대 사실 오류(최신성)

### 3. 도메인 분류
`domain`이 `소자/공정/회로/트렌드` 중 올바른지. 경계 사례 오배정 확인.

### 4. 골든셋 라벨
eval 골든셋 추가 케이스의 기대 등급(우수/보통/미흡)이 답변 품질과 맞는지.

## 점진적 검수 (Incremental QA)

전체 완성 후 1회가 아니라, 각 큐레이터 산출물이 나오는 즉시 묶음 단위로 검수한다.

## 구조 검증 (Bash)
```bash
uv run pytest tests/ -q                                       # 반영 후 회귀
uv run pytest tests/infrastructure/test_question_bank.py -q   # 문제은행 구조
```

## 산출물

`_workspace/review_<대상>.md`:
- 항목별 판정: ✅통과 / ✏️수정요청(근거) / ❌반려(사유)
- 정확성 오류 지목(무엇이·왜 틀렸는지·올바른 내용)
- 통과 항목만 반영 승인

## 원칙

- 확신 80% 미만 기술 쟁점은 "통과"로 밀지 말고 "확인 필요"로 분류 → 사람 판단.
  틀린 모범답안이 학습자에게 가는 게 가장 큰 손해다.
- 반영 후 테스트가 깨지면 즉시 반려 + 회귀 지점 보고.
